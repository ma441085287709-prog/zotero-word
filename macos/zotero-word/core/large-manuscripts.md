# 长稿执行与耗时

分别统计引用位置、独立论文和待插入位置。已有动态引用转投复用字段，CSL 切换无需逐条重插、重导入或重搜已核实文章。A 不提前做全文期刊格式；其全部完成后才询问 B，明确“是”后另存并排版。

统一开始/继续入口根据当前稿件和已绑定基准分流，按真实 next_action 推进；运行索引不证明动作已执行。见 [运行控制](run-flow.md)。已有活动域转投也要覆盖检查所有引文与 References，不能把“无需重插”等同于“无需验收”。

## 批量准备和库操作

prepare --brief 一次建立位置队列和库索引，按规范 DOI/URL/作者年份去重检索键而保留所有位置。按 [批量操作](batch-operations.md) 派发实际工具支持的批次，批量取得元数据；明确候选仍须身份/上下文核验。已有确认仅在输入、线索与身份未变时复用。

- 导入前查库，已存在则复用；只导入核实且确实缺少的记录，导入后取得真实 URI。
- 部分成功或无回应时重新读取库/集合，仅补未完成动作，不重放整个批次。不把写入请求返回当保存成功，也不伪造版本或快照新鲜度。
- 集合只执行当前差集，加入/移出成员；不重建集合、不删总库、不自动 Merge。
- 新引用默认按 [混合批量流程](hybrid-citations.md) 一次形成完整位置计划并预检，脚本写入独立副本；保存 citationID/URI、源/目标哈希与差异回执。模型不逐处重新组织查找、删除、搜索、选条目和接受动作。
- 不生成 `ZOTERO_ANCHOR_*` 等可见定位文字。源稿已经含有旧生成标记时，先核对其来源与修订历史，不能继续叠加新标记或仅清除活动显示。
- Word 阶段集中做真实识别、一次必要全量更新、书目与保存关闭；不为每个字段反复读取含全篇正文的 AX 状态、全库检索、渲染整稿或生成全量报告。
- 一个桌面一个执行者，安全动作和必要观察集中派发，焦点、选区和弹窗仍按真实状态判断。
- 同一 Python 执行内的只读检查复用绑定同一文件字节、规则与代码的解析/纯预期计划，模型读摘要，完整证据留文件；下个 CLI 进程重新解析，最终/native/用户决定不入缓存。开发回归不进入日常循环。

宿主已有且经验证的 MCP/CLI 可承担批量库动作，缺能力则用实际可用的文库通道。文库批次与 Word 字段批次分别记录；不能将库导入成功当作 Word 批量写入成功。写入器依赖缺失时先按本地连接规则准备任务所需运行时，新增安装或访问按具体授权处理；结构不支持时报告具体位置，不静默回退为大量逐处 UI。

已健康且获既有授权的 Local API 可由 [真实执行器](library-execution.md) 处理支持的批次；仅生成 host 工具请求时仍待实际派发和动作后核验。连接失败、403 或只读能力明确报告具体缺项并转现有 UI，不把空响应当作空文库。

## 原生全量更新次数

把本批引文、元数据、样式和书目变更集中后，完成一次必要最终全量更新。桌面执行器集中完成样式设置和书目插入，然后执行一次明确的最终 Refresh。预览、只读核查或取消未改编辑不增加全文扫描。

常规引文使用最终真实刷新及 Word 保存关闭回执。后续相关修改、自动更新仍延后、实际未更新项或原生任务未完成时才补做。判断依据是日志、偏好、全字段/书目结果与保存状态，不是按钮次数。不能省结果核验，也不能用反复 Refresh 代替核验。

批量写入阶段不逐条触发插件更新。后续确需逐处原生插入且本稿实际插入慢或预计大量新增时，可在工作副本记录并临时关闭 Automatically Update Citations，最终恢复原值。原值关闭的稿件仍需一次真实手动全量更新，并说明后续需手动更新；不改其他稿件或全局设置。临时编号/警告不是最终结果。[Zotero 长稿说明](https://www.zotero.org/support/kb/citations_slow)（既往核查 2026-11-10）。

## 可选 B 的效率边界

A 已验收的引用完成稿和基准先保留，未明确选择“是”不读取 B 的全文规则、创建角色图或写格式。B 覆盖全部普通段落和目标角色，以文档专用样式集中应用实际差异；不要把正常继承值展开为成千上万项重复直接属性。全文覆盖与按角色批量应用应同时满足。

B 先形成有来源的格式规则及允许变化计划，再在 A 的新副本执行。不改全局模板，不重建整份 DOCX，不把通用 run 合并当作 Zotero 安全保障。B 的科学内容和动态域仍保护，References 沿用 A 已核实的 CSL 与八项规则。

纯排版不重新同步集合、不重复确认同一版本、不无故调用 Fields.Update 或 Zotero Refresh；真正影响引文/书目时才更新并重验。B 仍须保存重开、检查关联及全文实际布局。记录 B 自己的耗时与状态，失败保留 A，恢复只补 B 缺项。

B 原生保存后读取新 B 的实际字节，重新核对目标格式、科学内容和动态关联；只有不变的 A 解析及纯预期计划可命中 memo。不得用旧 B 结果或旧 PASS 加速放行；全部普通段落/角色和全部引用仍须覆盖。缓存边界见 [执行效率](execution-efficiency.md)。

## 观察、等待和恢复

原生长稿更新可能占用 Word 较久。UI 超时、静止进度条或高 CPU 既不证明死锁，也不证明完成。查本稿日志、保存稿及真实原生阶段，判断是否部分写回、书目/偏好是否提交、是否仍有活动任务。未结束时不再派发 Refresh，也不将部分保存稿标为完成。

持有本稿操作锁期间，其他执行者只检查状态；忙碌反馈包含等待或重查下一步，不发第二个原生更新。进度只用已核实位置/批次和实际阶段，无观测百分比或预计剩余时间则留空。

中断先重查状态，再补缺失步骤。一次有依据恢复后相同故障仍复现且状态无实质变化，停止该动作；不换提示词继续重试，不强杀进程、改数据库、无差别重装或扩大权限。混合新旧引文须报告未完成，不能按表面停止位置猜故障记录或根因。

## 附件和计时

缺 PDF 不阻塞已解决引用。合法全文下载后置、集中尝试，缺失记清单；必须阅读全文才能判断的论点核验仍需在正式转换前解决。

分别记录检索、导入、字段写回、样式/书目更新、保存关闭、集合、A 核验、用户选择和 B 排版/核验的起止与工具次数。模型/工具/应用/人工等待不能分摊时标未知。没有同稿同环境测量，不承诺倍数、分钟上限或将短稿速度外推。

批量准备和实际原生刷新分开计时。运行目录中的状态记录属于当前稿件，供中断后继续使用。
