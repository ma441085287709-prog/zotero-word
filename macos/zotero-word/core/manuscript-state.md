# 稿件状态和集合同步

本页用于另行请求的集合与完整基准维护。日常动态引文交付以[正式运行记录](run-flow.md)的刷新、保存关闭回执和交付文件指纹为准。

本页属于通用核心；需要操作 Word、Zotero 或外部资源的步骤，由所选平台适配器使用其真实可用工具执行。

## 认可基准

稿件集合跟随用户认可的当前稿件；文件名、文件修改时间、正文长度及上传顺序都不能自动决定哪个版本优先。新稿首次建立关联，默认集合名取稿件文件名，放在个人库；若同名集合已存在，先核实身份，不能创建第二个同名集合来掩盖问题。

仅在委托包含集合同步时记录本轮授权及选定基准。普通引文任务在 Zotero 刷新、Word 保存关闭后交付。集合委托范围不明确时，只澄清需要变更的集合及稿件。

改名、另存或换路径时参考先前记录、相同 citationID/URI 及内容关联；确认是同稿就复用集合。身份不明时集中询问“继续原稿 / 作为新论文”。仅凭同名文件不能建立关联，仅凭名字变化也不能另建集合。

运行记录保存在稿件工作目录，不能放入 skill 安装目录。保存：稿件身份及路径别名、输入哈希、库身份、集合身份/路径、确认映射、原生样式 ID/自定义 CSL 路径与哈希、认可基准、当前阶段及已完成操作。区分初始与当前/最终状态，附实际观察时间；已有结果保存路径及哈希，避免每次重新提取和输出全文。使用本包可追溯 JSON 及必要的邀请/决定/阶段回执，不为不同模型另建平行日志协议，也不要复制整个个人库到 skill 包里。可由所选适配器从已证明的连接接口记录集合 key；只能取得名字时，同时记录库、父路径与实际选中观察，同名无法区分则停止。

新基准只能在全部引用确认、逐位置覆盖/正文保护审核、元数据与论点核验、真实 Word 全量更新（成功样式转换可计入）、保存重开关联、集合验证和引用相关视觉检查成功后写入。失败保留上一基准，另记待续状态；不要把“点击了刷新/保存”或 `verify PASS` 当成整体完成。完成回执按当前保存稿哈希绑定实际证据；`baseline` 必须重新读取输入、输出和回执并审核，不能只凭一句最终检查说明推进。

2.0.0 的阶段 A 基准范围仍为引文、References 和稿件集合，completion_scope 保持 citations_and_references。须有当前引用规范、真实 CSL、书目八项、身份/正文保护、原生更新、保存重开和引用视觉的实际结果；不要求全文角色图或排版回执。历史证据不改写为本轮通过。A 成功后冻结可交付的引用完成稿及其哈希，不能让后续选做排版覆盖它。

## 引用完成后的排版选择与状态

用户另行要求全文排版时，绑定已验文件与期刊，并将这项请求记录为排版决定。同一委托可以直接沿用。

选择绑定本轮 A 文件路径/哈希、基准哈希和目标期刊。明确“是”才创建 B 的规则、角色图并执行；“否”保留 A，未答复、默认选中、超时或关闭窗口均不算同意。有效选择在同轮恢复时沿用，不重复问；A 保存内容、基准或目标期刊变更，旧邀请/选择失效。集合版本同意不能替代全文排版同意，先前其他稿件的“是”也不能复用。

| 状态 | 结果与允许动作 |
| --- | --- |
| A 未通过 | A 保持 HOLD，不发起 B，不建立虚假的引用完成稿 |
| 引文任务完成 | 交付已验引文稿。另行收到全文排版请求才启动 B |
| 拒绝 B | A 仍完成，B 记 declined；不读取排版规则或生成角色图 |
| 明确同意 B | 检查绑定仍有效，另存 B 后记 running；按 [可选全文格式](optional-layout.md) 执行 |
| B HOLD/中断 | 保留 A 原件和基准，保存 B 诊断状态；不把部分排版稿标完成，不回退 A 状态 |
| B PASS | B 文件与 A 基准关联，独立保存验证和视觉证据，才报告全文格式匹配完成 |

A→B 只允许计划内格式变化，科学文字、数据、公式/图像内容、其他域及真实 Zotero 身份不变；同时复核 CSL 和 References 八项。不能把 B 自己当来源自比对，不能用关闭 A 正文保护绕过允许变化计划。B 纯排版不重新同步集合、重问同一集合版本或推进新的引用内容基准；若引用内容/身份实际变化，先返回 A 处理并使旧 B 选择失效。

## 集合差集

设保存稿件内有效引文的唯一库身份集合为 D，目标集合的实际成员为 C：

- 加入 `D − C`；
- 移出 `C − D`；
- 保留 `C ∩ D`。

次数来自全部被纳入的引用位置：同篇删一次但仍有其他位置时不移出；最后一次删除才移出。移动引文、改 CSL 或单纯重编号不改变成员集。仅在本稿集合使用“从分类中移除条目”；不得拖入废纸篓、删除总库记录或改变其他集合。总库保留需用原 URI 的实际库记录再次核验，不能只从所点菜单推断。

集合顺序不控制引文编号。保留一份稿件首次出现顺序用于核对，实际编号/作者年份由 Word 中的位置和目标 CSL 决定。不同样式不一定采用数字顺序；不要对所有 CSL 强制检查 `[1]`。

已管理稿件删去全部引用时，目标集合可以为空，但“脚本没读到引用”不是清空依据。需要已有基准、本次更新同意、按约定范围逐项确认确无活动/静态/未解决引用，并在 Word 原生检查/刷新后确认无旧 References。保存相同状态的零引用审核回执，才使用脚本的 `--empty-review` 分支；默认零引用状态保持 HOLD。不能为一个从未完成动态转换的纯文本草稿签发零引用回执。此分支属于需单独核验的特殊修订，不冒称先前短稿原生验收已覆盖。

## 状态证据和脚本

`core/scripts/zotero_docx.py` 的核心检查使用 Python 标准库，无需直接访问 Zotero 数据库或凭证。A 的检查和批次计划命令读取文档/导出并写 JSON，不创建 Word 域或执行集合动作；实际库操作由适配器完成。新增的 hybrid-* 命令需已发现的 lxml 运行时，可按绑定真实库身份的精确计划向独立副本准备兼容字段；写入后由正式入口完成本稿的 Zotero 刷新、Word 保存关闭并交付。见 [混合批量写入](hybrid-citations.md)。B 的 layout-apply 仅在已通过 A、有效明确同意及规则/角色绑定通过后，向新的排版副本写入受限格式；不覆盖 A、不生成引用字段。可执行示例、回执字段和退出状态见 [脚本命令](script-commands.md)，使用前也可读 `--help`；使用环境提供的 Python，路径包含空格时正常引用。

先 `inspect` 不变输入与实际保存的 `.docx`。扫描当前正文及其他 story 的域，列出逐处线索、文字与起止位置、citationID、库 URI、DOI/链接、出现次数、样式及异常。引用位置数与独立文献数分开保存，不能因为唯一 URI 集合相同就认为引用没有遗漏。其他 story 是诊断覆盖，不自动扩大约定的编辑范围；发现页眉、页脚或脚尾注等范围外引用时，先明确它是否属于本稿有效引用，未明确前不要直接据全扫描结果执行移出计划。正文的真实顺序应保留，表格文字不能跳过。遇到复杂修订造成域不完整、临时域或身份无法解析时先恢复，不能据不完整扫描计算删除计划。

库与集合的原生 CSL JSON 导出需绑定实际来源：库标识、目标集合、观察时间、过滤已清空和原始文件哈希。`bind-export` 仅把 **实际观察到的来源** 记录为快照，并不替 agent 证明它。不得为了通过脚本而填写没有发生的 UI 观察。空集合必须实际看到该集合无条目并清空搜索/标签过滤；导出禁用不是空集合的证明。

原生 CSL JSON 的 `id` 可能被 citationKey 替代，不能把任意字符串当作 Zotero URI。存在 citationKey、合并历史、跨库或孤立域时，先取得可信的条目身份映射；映射不明暂停，不能按题名猜 URI 或静默导入新条目来修复。快照时间限制只是附加检查；每次实际变更前都应在同阶段重新读取状态，避免用仍在时间阈值内但已过时的数据。

顺序为：保存并检查稿件 → 获取/绑定新鲜库与集合快照 → `reconcile` 得到加入/移出计划 → 由所选适配器核对当前状态并执行缺失动作 → 再次导出集合与库 → `finalize` 在一次调用中核对文档哈希、集合等式、库记录保留、覆盖、正文保护及完成证据，全部成功后建立基准。独立 `verify` / `audit` / `baseline` 保留用于诊断和分阶段恢复；新基准必需输入稿、覆盖清单及完成回执，旧 v1 基准仍可作为前一版本读取。具体可执行命令与参数以脚本帮助为准；不要把计划执行前的快照复用成“执行后导出”。

批量执行的部分成功、未知结果和恢复按 [批量操作](batch-operations.md) 记录实际状态，导入或集合动作超时不能整批重放。若稿件、库记录或集合在计划后又变动，旧计划失效，重新检查并生成差集。用户对当前稿件版本的授权未改变时不重复索要同一授权；但不能借此执行旧计划中已不再需要的移出动作。

## 二次核验和继续执行

本任务中的“二次核验”指 **检查实际状态，然后补做缺失步骤**，不是机械再跑一遍全部动作，也不是单指文献多源交叉核对。

先查本稿日志、保存状态和原生任务是否仍在运行，判断上次操作是否完成。UI观察超时、无响应、静止进度条或输入派发成功，均不能单独据此断言死锁或重发；用保存稿、当前域、原条目及实际成员核对，再决定是否还缺动作。对同一动作记录目标、错误类别和当时文档/库/界面状态。只有明确恢复依据时可补做一次；相同动作、相同错误且状态没有实质变化时，停止该动作及依赖阶段，保留可继续部分和具体阻点。改变提示词、参数拼写或模型的猜测不算状态修复。

用户完成所需操作、实际修复了焦点/预览/记录，或文档、库、工具能力发生相关变化后，重新核对状态并记录新的恢复依据，才可开始下一轮。不能仅更换调用形式就重置重试次数；不能强制杀进程、修改数据库、重装或扩大权限来延长恢复。最终真实全量更新、保存重开、身份与正文保护核验仍需完成；已实际完成的样式转换可计入更新，不因只读重查机械追加Refresh；未通过则保留上一基准。

| 中断位置 | 恢复时先查 |
| --- | --- |
| 创建集合后超时 | 原库是否已有本稿集合，避免同名重复创建 |
| 导入文献后无回应 | DOI/标题是否已存在、是否取得真实条目 URI |
| 接受引文后延迟 | 保存文件/当前 Word 是否已有该位置的完整活动域，预览/临时域是否完成 |
| Refresh 后立即 Save | 实际显示和落盘结果是否都已更新，不能只看缓存文本 |
| 集合动作中断 | 重新导出当前集合，只执行仍存在的差集 |
| 合并之后 | 幸存条目和历史身份是否可解析，旧计划是否需要重建 |
| 保存关闭重开 | 实际选中引用域打开 Add/Edit Citation 能否恢复原条目；此前最终更新后的保存结果是否保持，取消未改编辑后不追加全稿更新 |

B 恢复时先核对 A 的文件/基准/期刊及明确选择仍有效，再查当前 B 结果和待补步骤。纯格式失败不重跑已完成的 A，不改写 A 基准，也不把原先的集合确认当作 B 同意。

恢复不自动接受其他用户尚未确认的候选、合并、版本更新或排版选择。与当前任务无关的文档不打开不修改。
