# 引用完成后的可选全文格式

常规 Windows 引文任务在 Zotero 刷新、Word 保存并关闭工作副本后交付。用户另行明确委托全文排版时，从这份交付稿新建排版副本。

## 启动与文件

Windows 可将已完成运行的 `run.json` 用作 `--baseline`。以 `layout-offer` 绑定引文稿路径、指纹、目标期刊和对应的 `--reference-profile`。用 `layout-decision` 记录用户对该稿件的排版请求及其来源，同一次明确请求即可。续办沿用仍有效的决定。若期刊、稿件或任务范围尚不清楚，先向用户澄清具体项目。

选择是后，`workflow_state.authorize()` 每次重新读取实际 offer、decision、基准、A 和引用档案；仅匹配当前保存稿的 yes 才可运行 `layout-apply`。B 必须为新文件，禁止覆盖 A、已有 B、基准或证据。写入器先生成临时副本并验证，验证通过才发布 B；中途失败删除临时文件，A 与其引用基准继续有效。

## 期刊规则与完整覆盖

用户明确选择 B 后才加载全文规则、建立角色图和执行排版。此前只做 A 需要的保护性检查，不提前制作全文角色图或把它作为 A 的完成条件。

明确选择是后，公共 `layout-paragraphs A --decision DECISION --baseline A_BASELINE --output PARAGRAPHS` 提供逐段文本和哈希；内部只读实现为 `layout_format.inspect_paragraphs(A)`；按实际内容审阅主 Word story 的标题、副标题、作者/单位、摘要、关键词、各级标题、正文、图注、表题、表注、可编辑表内文字及公式所在段落。所有普通段落都必须有角色，不把全文转换缩成局部示例。原生动态 Bibliography 的非空条目、实际 begin→end 范围内的纯书目空段（包括仅含 end 标记的结束段）自动排除，继续归 A 的八项规则和真实 CSL 负责。只有书目之后整段尾部全部为空、无正文/图形/表格/域或引用锚点，并显式沿用书目样式的生成空尾才同样排除；附录及其普通空段仍须映射和检查。Word 可在这些确属书目的空段恢复 Bibliography 缩进，不能因此强写成 body 的零缩进。页眉、页脚、脚注等其他 story 以及图形、Office Math 内容原样保留；如期刊另要求修改这些对象，应明确支持范围和独立核验，不能默认已经处理。

全文档案为 `zotero-word.optional-layout-profile.v1`：包含 `journal`、`article_type`、`submission_stage`、`roles` 和 `page`，二者均必需。它不包含 CSL、引文编号或 References 规则。角色图为 `zotero-word.optional-layout-role-map.v1`，绑定实际 A 的 `source_document_sha256`，每段有 `story`、`paragraph`、`text_sha256`、`role` 和审阅 `evidence`。

每个目标值必须是 `{value, basis, evidence}`：`basis` 为实际期刊投稿要求 `required` 或明确说明的 `workflow_default`；区分初投、返修与出版 PDF 样式。期刊允许自由格式或未规定数值时，不捏造强制字体/页距。每个角色必须明确字体、字号、行距、段前后、三项缩进和对齐九项；标题角色另有对应层级。页面必须明确四边距及宽高六项。保留适合现值时仍须填写实际数值并核验，空角色或空页面规则不能表示已完成全文匹配。

支持普通文字字体、字号、角色基准粗斜体，段落对齐、行距、段前后、三项缩进、标题层级、分页/段落保留，以及现有节的页距/纸张大小。直接或字符样式声明的正向行内粗斜强调保留；角色粗斜规则不统一清除科学名称、强调和原生引文字重。动态域内部、其他域、Office Math 与图像内容不由该格式器写入。

## 批量样式与效率

全覆盖和按角色核验，不等于逐 run 重写全部属性。格式器读取实际有效值；已等价属性不显式化。仅实际不同的段落规则用新的文档专用段落样式共享应用，且不修改原有共享样式。字体/字号等实际不符的普通文字用共享字符样式处理，保留原字符样式继承；不把字体和字号重复写进每个 run。

原稿→A 的普通格式保持门不放松。A→B 单独验证实际目标与允许变化，不能把 B 自己当源文件，也不能用整段“已审阅”豁免文本/身份变化。生成器的“已应用待核验”只表示本地格式变换，不是原生 Word 或视觉验收。

## 保存重开与 B 验收

使用 Windows 的 `run.json` 作为基准时，`layout-audit` 直接调用包内执行器重开排版稿并抽检真实引文。完成审查中的 `visual_review` 记录实际目视结果，原生回执由执行器按该文件的哈希生成。对已另存的清洁稿可使用[运行说明](run-flow.md)中的 `run-verify-copy --clean`。

按主命令说明使用 `layout-audit` 验收当前保存的 B。核对全文角色/页面实际有效格式、科学文字和控制符、公式/图形、其他域、真实 citationID/URI 与引用位置；再次核对实际 CSL 和 References 八项，确保普通排版没有覆盖引用编号或书目粗斜体。使用实际 Word 保存、关闭重开并核对已有引文关联，渲染和实际查看全文页面，检查标题、图表、分页、溢出及引用可读性。

纯排版没有改变文献、域、CSL 或书目相关状态时，不重复同步集合、不重复询问稿件版本，也不机械追加 Zotero 全量 Refresh；确有相关修改或结果异常时才执行必要更新并复核。必须保留 A 的引用基准，B 是与它关联的排版版本。

A 已完成而 B 尚未选、被拒绝或失败时，分别报告“引文与 References 已完成；全文格式未执行/未完成”，并给出 A。B 选择为是且全部必要核验完成后，才报告“全文格式匹配完成”。不把只生成的排版副本当作完整成功。

对无法安全解析的复杂修订、条件表格格式、特殊符号/字体或嵌套容器保持 HOLD，指出具体范围并保留 A。不得为通过校验清除科学内容、取消修订或重建整稿。
