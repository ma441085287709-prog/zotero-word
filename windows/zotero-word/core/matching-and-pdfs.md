# 文献匹配和全文附件

本页属于通用核心；需要操作 Word、Zotero 或外部资源的步骤，由所选平台适配器使用其真实可用工具执行。

## 从实际稿件建立映射

先对不变输入运行 `inspect`，提取每个引用位置的片段及必要前后文，记录 `cue_id`、story、段落、片段起止位置、原始 DOI/链接/作者年份/编号、原有 Zotero citationID（若有）。已有活动域以 `field:<citationID>` 对应输入位置。不要先改写再寻找原作者线索；实际写入前再次核对工作稿相同位置。

`inspect` 逐处提取括号式或叙述式作者年份、静态编号、裸 DOI、DOI URL、文章 URL，以及显示文字与真实地址不同的外部超链接。提取只提供候选和位置，不证明 DOI 可解析、链接指向论文或文章支持原句。复杂句、跨段编号、文本框、扫描图中文字及未支持的链接结构仍需语义检查；不可因脚本未识别线索就声称稿件没有引用。图片内文字无法直接改成 Word 域时说明具体位置并集中确认处理方式。注释批注不是证据来源；修订默认看当前文本，删除和 moveFrom 不计入；若目标修订视图不同先明确。

已有引用的处理：

| 输入 | 做法 |
| --- | --- |
| 已有完整 Zotero 引文 | 读取并保留身份，检查能在原库解析；不因内容相似而重插 |
| 裸 DOI、`DOI:` 前缀、doi.org 链接 | 提取规范 DOI，优先查个人库，再通过注册机构或出版社核对文章；不可仅凭字符串格式通过身份核验 |
| 出版社 URL 或隐藏的外部超链接 | 同时记录显示文字与真实目标，优先取 DOI/可靠元数据；普通网页不能未经核验当作论文 |
| 手工数字编号与静态 References | 先把每个编号对应到完整参考文献，再逐条核实 DOI/题名/作者；同一编号对应不同文章、缺书目或孤立书目集中处理 |
| 作者年份叙述 | 用作者、年、技术细节、研究对象和结论范围检索；不要将文字改写顺序当成引文顺序 |
| 混合稿件 | 合并上述映射；同一论文跨输入形式统一到同一原库条目 |

## 搜索与判定

优先使用现有 Zotero 个人库条目、已附全文和摘要；通过所选适配器读取条目或取得新鲜的原生导出。有明确标识符时先核对标识符，再用标题、作者和年份交叉核验；没有明确标识符时用题名或作者年份与上下文找候选。候选不足时，用 DOI 解析、出版社/期刊、机构仓储及其他权威书目来源补查。只向外部查询必要的公开书目信息，不上传整份未发表稿件或整个个人库。PMID、arXiv ID、ISBN 等可由 Zotero 支持的标识符通道处理，但不因通用表述就声称脚本已具备相应自动抽取器。

核对三个不同问题：文章是否存在且出版信息可靠；该文章是否支持这句话；对应哪一个实际 Zotero 条目。DOI 唯一且元数据正确，并不自动证明它支持稿件论点。

同一轮用 `prepare` 按规范 DOI、URL 或作者年份检索键集中枚举候选；一组可服务多个位置，但各位置的原句和上下文分别保留。仅在核心版本、输入哈希、实际库快照内容及查询均相同时复用确定性枚举结果；任何一项变化都重新计算受影响查询。无库快照是“尚未查询”，不能报告“库中不存在”。 批量查询、元数据获取、入库和集合任务使用 [结构化批次](batch-operations.md)：检索键去重而位置不丢失，按实际工具能力限制批量大小；计划绑定输入和库状态，部分成功分别记录，未知结果先重查，不整批重放。批次状态不能代替逐位置的语义核实或实际库身份。外部结果可复用已核实文章身份和来源，但每个引用位置仍检查论点支持；不能把检索分组当成引用位置合并或确认复用。最终核验必须基于当前真实文档和库状态，不能被候选缓存替代。

- 姓名转写、连字符、姓名顺序与 et al./等可用于放宽候选搜索；不能用于忽略作者身份冲突。
- 比较期刊卷期年、在线发表年和预印本年，不强行改成与草稿相同的年份。草稿年可能写错，需要确认文章身份与原句是否一致。
- 同作者同年多篇论文必须看具体过程、材料、对象、数据或目标；排序第一、标题相似、引用量高都不是充分依据。
- 限制原句的范围；不能用“处理了类似废水”支持某个材料机理、定量性能或特定工况。
- 记录真实存在的出版信息。没有 DOI、没有期号、使用文章号或尚未分页都是可能的真实状态，不虚构补齐。

对每个位置记录 `resolved`、`needs_choice`、`not_found` 或 `conflict`，以及候选 DOI/标题/年/期刊、库 URI 和证据。明确项自动落为 `resolved`。外部文章尚未入库时可明确文章身份，但必须在正式插入前完成入库身份核对。

在绑定输入和输出哈希的覆盖清单中，为每个输入位置记录目标活动引文及预期库 URI，或有依据的非引文、仅书目、经用户确认移除等处置。静态 References 的条目先与正文位置对应，未被引用的条目可明确记录为仅书目；不能将正文缺失位置归入该类来绕过。三处引用可能只有两篇独立文献：重复文章复用条目，不代表可删掉其中一处引用。不同句的引用不得仅为达到预设数量而合并或移除。记录与审核方法见 [脚本命令](script-commands.md)。

一次集中提出需要用户决策的问题，原句与位置足够让用户定位；候选要给出能区分它们的信息，而不是只给作者年份。未找到的项可请求标题、DOI、PDF 或进一步线索，但不要编造一个看似相关的替代引用。所有阻断问题解决后才统一正式转换；缺 PDF 除外。

## 确认复用与查重

旧确认是针对特定线索、实质上下文、候选证据和条目身份的选择，不是“这个作者以后都用这篇”。记录精确线索哈希、所选 DOI/URI、当时可选文章身份和答复来源。线索/上下文改变、新增实质竞争候选、记录合并迁移导致身份映射不明、或论点与文章冲突时重新判定，必要时加入集中问题。仅因文件改名或 CSL 切换，不需重复询问未变化的选择。

查重在检索/导入前及导入后都检查，以本稿使用、候选、新增记录及其库内重复候选为范围。脚本若枚举出其他全库重复组，不借本次稿件任务清理无关记录；用户另有全库整理授权时再扩大范围。

同阶段未变的库快照可复用已生成的查重诊断；导入、合并、元数据或其他库状态实际改变后重新检查受影响范围，不为每一个重复引用重做全库枚举。任何重试前先查条目是否已经存在，不能以重复导入代替读取当前状态。

- 同一文章多次引用：复用条目与编号，不合并 Word 引文位置。
- 同一个 Zotero item key 属于多个活跃集合：正常交叉收录，不是重复记录。普通书目、独立附件及其子项分别计数；已删集合的历史关系不当作活跃分类，不因盘点而恢复它们。
- 相同规范化 DOI 的多个条目：重复候选；若标题/作者等严重矛盾，先视作元数据冲突，不能仅按 DOI 合并。
- 无 DOI 的题名、作者、年份、期刊与页码相近：疑似重复，需核实，不能自动合并。
- 同作者同年不同研究、预印本与正式版、勘误/撤稿通知与原文：不同出版身份，不直接合并。

合并前集中列出每组记录的差异、建议主记录、附件/笔记/集合情况和引用关联；用户明确确认后才用 Zotero 原生 Merge。合并后重新读取幸存记录及身份映射，重算集合计划，并把相关引文更新并入本批最终原生全量更新。不要删除一条再重导入来代替合并，也不要假定条目 URI 一定不变。

用户另行授权整库合并或集合重整时，先备份实际原始数据目录与本地附件；正常关闭 Zotero 后复制并核验，RIS/CSL 元数据导出不是可恢复的完整备份。保留附件、笔记、批注、活跃集合和已有 `dc:replaces` 替代关系，原生合并后记录旧 URI 到幸存 URI 的实际映射。集合移动保留原 key，核对已绑定稿件基准的完整路径，不能静默移动后伪造新基准。用必要的独立副本核验旧引用刷新/保存重开，不为整理库而逐份刷新所有历史长稿。

## 核验后入库与修正

复用已确认库内记录。只有确实缺少的文章才通过 Zotero DOI/标识符导入或经过核验的 RIS/BibTeX 等方式入库。优先使用已发现且已验证的批量工具集中导入；没有该能力时主动检查当前适配器与必要连接，按任务授权准备通道；需要新增访问或依赖时准确说明并取得实际缺失的批准。导入后重新搜索目标 DOI/标题，核对标题、作者顺序、正式年份、卷期、页码/文章号和库身份，再附到本稿集合；导入返回或弹窗关闭不代表已完成。重试前先查是否已经入库。

书目元数据与样式问题分别处理。权威证据明确的书目字段错误按用户任务范围修正并记录前后值及依据；身份、出版版本或来源相互冲突时先确认。样式里的作者缩写、标点和上标不通过篡改作者姓名或标题来实现。变更库记录后，把本批修正集中更新一次并核对保存的Word内嵌数据；已完成全量样式更新且包含最新元数据时不重复Refresh。

输入操作返回不代表条目保存成功。编辑后离开字段、切换条目再返回并读取/导出核对，本批结束后按实际需要完成一次原生更新、保存并检查书目，不逐项修正就全稿Refresh。发现 `(0 ed.)` 等已知错误时先核实真实版本并修正源条目；不能为了隐藏错误清空正确字段或手改 Word 书目。尚未保存成功的修正属于未解决项，阻止正式完成及新基准，保留诊断后等待可靠写入通道。

## PDF 获取

已有附件先复用，确认能打开且确为所选文章。没有附件时自动尝试：出版社 OA 下载、机构/学科仓储的合法开放版本、Zotero 原生 Find Available PDF，以及用户已具备访问权限的正常渠道。通过所选适配器提供的浏览器/连接工具和既有登录；不要绕过付费墙、验证码、访问限制或请求新购买。遇到必须由用户完成的登录/权限步骤时说明所需操作，其余工作可继续。

取得后核对 PDF 的 DOI/标题/作者或正式版本信息，排除补充材料、摘要页、下载错误页面和同题不同版本；再用 Zotero 原生附件功能附到正确条目，验证关联并复用，不反复下载副本。对预印本/接受稿注明版本，不能冒充正式出版版本。

下载失败记录文章身份和原因即可；论文身份、上下文支持与格式问题均已解决时，缺 PDF 不挡正式引用转换。交付报告列出缺失清单；不要暗示已经阅读全文。
